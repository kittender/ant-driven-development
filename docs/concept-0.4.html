Ant-Driven Development

A way to build software with many small, short-lived AI agents that never talk to each other. They leave signals in the code, deterministic programs sense, count and check, and nobody is in charge. Since 0.4, small models are not asked what they think: the harness reads it from their probabilities.

The idea

A single large agent loaded with a complex task accumulates sunk cost. Its context fills with its own assumptions, and when one of them is wrong it tends to loop on it. The usual fix is an orchestrator directing sub-agents, which moves the problem up one level.

Ant colonies solve hard problems differently. Each ant is simple and replaceable. Ants coordinate by changing their environment: one leaves a chemical trace, the next reacts to it. Traces evaporate, so mistakes fade. No ant holds the plan.

Ant-Driven Development (ADD) applies that to software. An ageant is a small-model agent that does one tiny job on one target and then dies. Ageants leave emoji signals in the code. A set of deterministic programs, the Ecosystem, counts those signals, lets them decay, and checks every claim of success. A large model, the Queen, only designs new kinds of ageants when the colony lacks one. Approved specification is stored as honey, and how the software is built is kept in a garden of small plans.

Level 0 sharpened who does what:

  • Instruments sense what a program can measure: coverage, the compiler, lint, duplication, git recency, path rules. Most signals start here.
  • Small models are read, not asked. A probe answers one typed question and the harness reads the probability of each answer. The word a model writes is only the most likely token of a biased distribution.
  • Humans own what nobody can check: intent, contracts, and the final say on wording and visual changes.

Work that needs context stays near home: the Ecosystem groups the code into code zones, clusters of a few related files, and feeds each probe its zone. Discovery stays free: scouts roam across zones, and patrollers watch the edges between them.

The three hopes of 0.3 stand: changes small enough to follow, contexts small enough not to degrade, and work that runs mostly on models on the developer's own machine. The third is now shown for perception, on fixtures, and not yet for code changes.

Three layers

Intelligence is spent where it is cheapest to verify. The largest model works rarely and only on design. Small models do the volume. Everything that must be predictable has no model in it at all. 0.4 adds two boxes: probes in the colony, instruments in the Ecosystem.

Castes

A caste is a genome: a short prompt, a closed list of tools, the signals it reacts to and may emit. The harness enforces the tools, so a worker cannot kill a process even if it decides to. 0.4 changes how the reading castes decide, and adds probes.

A probe panel

One probe holds one signal and one question. The harness asks it twice, with the two answers listed in both orders, reads P(yes) from the token probabilities, and averages. Listing one answer first moved some probes by up to 0.33, so both orders are a harness rule. The probes of one target share their whole prompt prefix, so nine probes cost about 10 seconds per target on a laptop.

The scout stays, with a narrower job. Its notes describe code accurately even when its choice is wrong, and the scout and the probes fail on different targets: on the held-out set, probes alone were right on 5 fixtures, the scout alone on 3. The scout writes the note that reaches a worker and decides where no exam-passed probe exists. Where the two disagree, the target may deserve a 👀 (proposed, not yet tested).

Worker is still the broadest caste, and most genomes the Queen writes are workers: tester, debugger, scaffolder, ripener (refines specification) and undertaker (removes dead code and expired journals).

Where the biology is stretched. Leafcutter gardeners are the smallest workers in the nest; ADD gardeners run on the largest models, so the name borrows the job and not the size. Real soldiers face outward. The closer model for ADD soldiers is social immunity: workers that remove infected nestmates.

Code zones new

The Ecosystem groups the code into code zones: connected clusters of 5 to 10 files that import each other, change together, and fall under the same plots and honey frames. Judgment that needs context happens inside a zone; discovery and checking happen across zones. Ants do the same: workers keep returning to small areas of the nest, and nearness to a task largely decides who does it.

A program draws the zones, never a model. A zoning instrument builds a graph from imports, files changed together in git, and the targets of plots and frames, then runs Leiden community detection. Leiden guarantees that every zone is connected, which Louvain does not, so no ageant is fed files that have nothing to do with each other. Three settings keep it physics: a fixed seed, the previous run's zones as the starting point so zones move only where the code moved, and a resolution that keeps zones at 5 to 10 files.

  • Context. The zone's plots, honey cells, contracts and one reference neighbour go into the stable part of every probe's prompt, kept to about 2,000 tokens.
  • Cost. The prompt cache is keyed by zone, so a zone is read once for all its probes.
  • Strength. The Sensor also counts per zone. Many 🧹 across one zone wake one gardener for a zone plan, not one refactoring worker per file.

Tested before adopted. On 14 fixtures where the right answer depends on a neighbour, the same probes ran with and without the zone. With it, mean AUC on 🧩 and 🧹 rose from 0.51 to 0.88 (4B) and from 0.63 to 0.85 (8B), false alarms on fine targets fell from 12 to 2, and a bug in a neighbour did not leak onto a fine target. 🐛 stayed weak inside the suite. The zones were drawn by hand; Leiden on a real repository is the next level's job.

Two kinds of zone. The harness architecture also has trust zones: the human, the Ecosystem, the ageants. They are about who may touch what. Code zones are about which files belong together, and every program that draws or reads them sits in the Ecosystem.

The trail language

A signal has one form: an emoji on a target, repeated to show strength.

rechercher-credit.component.ts     ✅ 🧪🧪🧪 👀
rechercher-credit.component.html   ❌ 🐛🐛
credit.service.ts                  🔒 ⭐ 📌

Emojis almost never appear in source code, so the channel cannot be confused with comments, documentation, or the code itself. A program can find every signal with a plain text search.

Three classes follow. Measurable signals (🌱 🧪, most 🐛) come from instruments. Judgeable signals (👀 🧹 📝 🧩 ❓) come from probes that passed their exam. Owned decisions stay with a human, with a path rule as the floor for 🙋.

Verdicts, which only the Ecosystem or a human may issue

A verdict says "this is true". An ageant that could write ✅ would write it confidently when wrong, and the trail would then reinforce the error. Verdicts come from programmatic proof or from a human, never from self-report, and never from an instrument either.

Strength by repetition

Reinforcing a signal means adding one more of the same emoji. Decay means the Clock removing one at that signal's own rate. A threshold is a count, and a count only means agreement between different minds: an instrument and a probe that agree are two, two probes of one model family are one.

t0🧪Coverage finds an untested branch
t1🧪🧪A scout of another mind agrees
t2🧪🧪🧪Threshold reached, a tester is woken
t3✅Test added and passing, request cleared
elsewhere, t1🐛One probe panel suspects a bug
elsewhere, t3Nobody agreed. It evaporated.

Storage form and prompt form

The trail stores emoji; models read each signal as emoji plus name ("🧪 needs_test") and answer with the name. The glyph is for programs and humans, the word for models. Neither form won outright on the fixtures, but names moved individual signals strongly (🙋 from 0/3 to 3/3), so they are part of the interface design.

Attract, repel, and fade at different speeds

Army ants sometimes follow each other's trail in a closed circle until they die of exhaustion. The software version is an ageant retrying a fix that has already failed. Pharaoh ants avoid this with a "no entry" mark at dead ends; ADD has ⛔. The Sensor never sends the same genome back to a target carrying ⛔, and at the threshold it escalates: the target to a gardener, its honey cell back to ripening. Each signal has its own decay rate: a review request fades in minutes, a dead end is remembered for hours.

Where signals are written

  • One journal per ageant. Ageant leni03 can write to ant-leni03.md and to no other trail file. Instruments and probe panels are recorded in the Ledger with their own author.
  • One rendered view per folder. The Ecosystem writes a read-only trail.md at each folder root. Ageants read it and never write it.
  • Inline, when a signal concerns a block. A line such as // trail: 🧪🧪 ❓ sits above the block and moves with it.

Signals, not sentences

The closed menu is confirmed: under a JSON Schema every model gave a valid signal every time. What 0.3 did not know is how much the shape of the question decides the answer. Real ants manage with ten to twenty chemical signals and no syntax; ADD keeps one emoji, one meaning, strength by repetition.

Asking for the decision

Which signal fits?  → "🧪"
Is there a bug?     → "no"
Name what you found → "the question"
  • The format decides. With "no" listed first every receptor said no; asked to name a finding, models always named something, often the question itself.
  • Defaults leak in. phi4-mini answered 🧪 on 65% of cases where 10% needed it.
  • A word hides its doubt. "Yes" at 51% and at 99% look the same.

Reading the decision

P(yes | yes first) = 0.62
P(yes | no first)  = 0.48
mean 0.55 > exam threshold 0.31 → 🐛
  • Both orders, averaged. Order bias reaches 0.33 on some probes.
  • A threshold from the exam. On the 8B, the fitted threshold added 14 correct fixtures out of 39 over a fixed 0.5.
  • Doubt is visible. The Ecosystem sees how sure the model is, and ranks panels by it.

Nine rules, each from a failed run

  1. Thinking is off for micro-tasks. A thinking model spent its whole budget reasoning and answered nothing.
  2. Every field is required, in a fixed order. Optional fields were skipped.
  3. The note comes before the choice. With the choice first, models picked the first option and justified it.
  4. What the Ecosystem knows is a closed choice. Copied paths came back garbled.
  5. One ageant, one decision. In a multi-turn session a small model repeated its own last reply in 38 of 42 sessions.
  6. No yes or no in a fixed order. Listing "no" first made every receptor say no.
  7. A free-text answer must be checkable. The Ecosystem must be able to verify it: a quote found in the code, a file that exists.
  8. Read the decision, do not trust the word. Probability, both orders, the exam's threshold.
  9. Aggregate before depositing. One decision per target, from comparing calibrated scores.

Facts are evidence, not verdicts. When facts were written as code comments, models rightly did not trust them. Once facts were trusted, "tests pass" became a reason to see nothing: a fresh rewrite of an auth interceptor was called "tested and clean". So each fact says what it proves and what it does not.

The context stays small and holds nothing left over from another ageant's reasoning. A wrong assumption cannot be inherited, because assumptions are never passed along. Only the signal, the facts and the code are.

Life of a signal

In 0.3 a stimulus came from a scout or a failing build. In 0.4 it comes from an instrument first, and from a probe panel where no instrument can see. Everything after the deposit is unchanged.

Example: a new method with no test

  1. A worker adds cancel(). Coverage reports 0% of its 3 branches.🧪
  2. The probe panel on the file agrees: 🧪 is the top probe over its threshold.🧪🧪
  3. The threshold is reached. The Sensor wakes a tester that passed its exam, with the facts attached.🧪🧪🧪 🚧
  4. The tester adds one test per branch. The Prover runs them at the next heartbeat.✅

Honey, the colony's long memory

Unchanged from 0.3; Level 0 did not test it. The trail says what needs doing and evaporates. Honey is what stays: what the software is supposed to do, and how this team writes code.

A frame is one user story; each cell is one acceptance scenario, Given, When, Then, checked by one test. Practice cells say how the team writes code, each backed by a lint rule or a ⭐ example. A human caps a whole frame in one reading. Ageants can read the store and cannot write to it.

# honey/credit-search/search-by-amount.md      one frame, one user story
As a credit advisor
I want to search credits by amount
So that I can find a client's file quickly

🍯 Scenario: empty amount
   Given the amount field is empty
   When I submit the search
   Then I see "Montant requis" and no request is sent
   test: rechercher-credit.component.spec.ts > rejects an empty amount

Whoever writes the code cannot touch the test. The Warden never grants a code-writing genome a lease on the test of the same cell. Only a human uncaps a cell; uncapping sends it back to ripening, marks its test stale, and puts 👀 on the code built from it. The Prover can show that code matches a cell; it can never show that the cell is what the human wanted.

The garden, where the plan grows

Honey says what the software must do; the garden says how it is built. Leafcutter ants feed leaves to a fungus garden that small workers weed constantly. ADD's garden is the architecture: one decision per plot, steps that become 🌱 seeds when a plot is grown, gardeners on larger models who never write code, and patrollers who read changes against the plots, now on the edges between code zones.

# garden/credit-search/data-access.md          🍄
Decision   Components never call HttpClient. They go through CreditService.
Because    One place for caching and for mapping errors.
Proof      lint rule no-http-in-components
Contract   📌 credit.service.ts  search(criteria): Observable<Credit[]>
Steps      1. credit.service.ts#search
           2. rechercher-credit.component.ts calls the service

Change in 0.4: a plot meant to be enforced carries a proof. 🧩 was the weakest written signal at Level 0: the scout read garden violations as bugs. A probe fed its code zone now judges fit far better (AUC 0.76 with precision 100%), but a plot whose decision matters is still backed by a dependency rule, a lint rule or a type. The probe is the second line, for plots no program can check.

Gardeners review each other through the plots: one that supports a proposed plot reinforces it with 🌱, one that doubts it leaves ❓. When gardeners on different model families bring a plot to quorum, it is grown. Many 🧹 across one code zone now wake one gardener for a zone plan.

The Ecosystem

The Ecosystem stays the colony's physics, with no model in it and out of the ageants' reach. In 0.3 it only counted. In 0.4 it also senses.

SensorThresholds and waking, per target and per code zone. Runs the probe panels, applies each probe's exam threshold, and deposits for the panel. Schedules the panels of one zone back to back on one resident model.

Lowest level first, for perception too

The reflex, tool, plan ladder of 0.3 is kept for action. For sensing it gains a rung below: a program before a probe, a probe before a larger model, a model before a human. On the fixtures, 34 of 40 cases could have been raised by an existing tool. That is an upper bound until instruments run on a real repository.

Leases instead of good manners

"Never edit a file someone else is editing" cannot be left as a rule in a prompt, because prompts are followed most of the time and not all of the time. The Warden grants one lease per target, shown as 🚧, and it expires on the Clock. After a change lands, the target rests for a short cooldown, the way a neuron cannot fire twice in a row.

Autonomy is a setting

How much the colony decides alone is configured per kind of decision. The defaults keep intent, contracts, wording and visual changes with the human, and let the colony grow its own plans. The settings live with the Ecosystem, so no ageant can change its own freedom.

The colony log

One time-ordered log of everything every ageant received, produced and called, with the cause of each start. A deposit by a probe panel points to the probabilities it was read from, and those to the change or the instrument finding that asked for the panel. No ageant can read the log.

The immune system

In this colony the enemy is always inside: an ageant that loops, claims what it did not do, or carries a polluted context. The flag, quorum, kill and caution sequence of 0.3 is kept.

  1. Tag. A soldier compares an ageant's claims with the Prover's results and the diff, and flags the ID.@leni03 🚩
  2. Quorum. A second soldier, of another mind, reaches the same conclusion. A lone accusation fades.@leni03 🚩🚩
  3. Kill. The Warden, not a soldier, terminates the process.@leni03 💀
  4. Caution. The Ledger adds 👀 to every target the ageant touched.👀 👀 👀

The entrance exam, for every genome

In 0.3 only soldiers sat an exam. Level 0 showed why every genome needs one: a model that says 🧪 on two thirds of cases would flood the trail. The exam runs a genome on fixtures a human labelled, and it sets as well as admits:

  • its AUC, which shows whether it ranks cases at all (0.5 is chance);
  • its threshold, below which it stays silent;
  • its order bias, how much listing one answer first moves it;
  • its yes rate against the label rate, and its precision.

A probe passes with precision of 60% or more and a yes rate at most twice the label rate. A failing probe's signal goes to an instrument, the scout, or a larger model. The fixtures become the colony's calibration set, and labelling them is a recurring human cost: 7 of the first 40 were wrong or too thin until a human reviewed them. Canaries stay: known cases slipped into the normal flow, so a drifting threshold shows up there before it shows on the trail.

The body does the same. Immune cells that react to healthy tissue are destroyed in the thymus before they are released. In 0.4 every genome passes through that thymus, not only soldiers.

Diversity by design

Ants make independent mistakes, so numbers cancel them out. Copies of one model make the same mistake together, so numbers amplify it. Repetition only means something if the ageants that agree are different minds.

For now, diversity has to come from instruments. On a 16 GB laptop only one model family passed: gemma3:4b and llama3.2:3b fell back on one default signal, phi4-mini on 🧪, and qwen3:8b is the same family as qwen3:4b. Agreement between two Qwen probes is one mind asked twice, and two probes fed the same zone share its blind spots too. A roaming scout that read no zone is closer to an independent mind, and an instrument is one. The Sensor counts them that way.

  • Rotation across model families wherever more than one passes its exam.
  • Seeded variation of wording, temperature and example, recorded with every genome.
  • The Queen rotates too, so a single bias does not reach every genome.

Birth, death and the end of work

  • Birth for one stimulus on one target; death on completion; a maximum lifetime enforced by the Warden.
  • One ageant, one decision. The limit is in the harness, not the prompt: a deposit limit ends the session on the first accepted signal. A probe lives for one question.
  • The Queen lives for one design. Each need starts a new session that reads the templates, the honey and the genome records, exams included, writes its genomes and ends.
  • The colony is quiet when no signal is above its threshold and every capped cell is green. Activity resumes when the human adds intent, an instrument finds something, or a proof starts failing.

A colony is founded with a human who settles the core frames, plots and contracts, and labels the first exam fixtures. After that it alternates between work and rest. An alarm (🚨, for instance when the main branch stops building) lowers thresholds for the castes that can help, the way an alarm pheromone does.

The laws of ADD

Laws 1 to 7 and 10 to 13 stand unchanged. Two are reworded and three are new.

  1. Physics is not negotiable. Decay, thresholds, proof, identity and death belong to programs that ageants cannot reach or argue with.
  2. Proof before praise. A verdict comes from programmatic proof or a human.
  3. One ageant, one micro-task, one life.
  4. Signals, not sentences. One emoji, one meaning, strength by repetition. Ageants never message each other.
  5. The trail evaporates, the rest must earn its place.
  6. The Queen designs and never commands.
  7. Nobody kills alone.
  8. Agreement only counts between different minds. Reworded. An instrument counts as a mind of its own; two genomes on one model family count as one.
  9. Lowest level first. Extended to perception. A reflex before a tool, a tool before a plan; and to sense, a program before a probe, a probe before a larger model, a model before a human.
  10. Honey before code. Whoever writes the code cannot touch the test.
  11. Mark the dead ends.
  12. Planners never build.
  13. Autonomy is configured.
  14. No genome speaks before its exam. New. Every genome is run on labelled cases before release; the exam admits it and sets its threshold.
  15. Read the decision, do not ask for it. New. A small model's choice is taken from its probabilities, in both option orders, never from the word it writes.
  16. Judge near home, discover at large. New, adopted after the zones experiment. Probes judge inside the code zone a program drew for them; scouts roam free of zones; patrollers watch the edges.

The full requirements are in docs/harness-architecture-0.2.adoc. In short:

NeedWhat it means
Run one ageantA genome, one model behind a single interface, a closed list of tools, hard limits on steps, time and deposits.
Read a probeThe probability of each answer from the model's token probabilities, in both answer orders. A model that cannot give them cannot be a probe.
Enforce outside the modelWrite access limited to the ageant's journal and its leased target. Fixtures, exams, settings and the colony log out of reach.
Six programsClock, Sensor, Instruments, Prover, Ledger and Warden, driven by one settings file.
Facts and zonesFacts in their own trusted block, each with what it proves; code zones drawn by a seeded program and given to probes only.
One change, one commitEvery change can be attributed, proven, bisected and reverted separately.
A place for the humanCap and uncap, answer 🙋, label fixtures, read the log, pause the colony.

Known weaknesses

These are the places where ADD is most likely to fail. Some exist in any way of building software and are listed so that ADD is not held to a higher standard than the alternatives.

WeaknessWhat ADD does about itWhat remains
One model familyInstruments count as independent minds; scouts read no zone.Until a second family passes on 16 GB, agreement between models is one mind asked twice.
Fixtures by one authorHuman calibration; held-out sets labelled before any run; decision rules written before each run.39 + 16 + 14 fixtures from one author: a direction, not a measurement.
Facts written by handInstruments are designed to compute them.Whether real instruments give facts this clean is the next level's question.
Bugs inside a targetFailing tests and lint first; probe as second opinion.The 🐛 probe fails its exam in every run.
Zone blind spotsRoaming scouts, context-free instruments, zones redrawn as code changes.Probes fed one zone share its mistakes; zone drift is not measured yet.
Nobody holds the planThe garden holds it, in plots small enough to review one at a time.Whether many small plots add up to a sound architecture is untested.
Proof is only as good as the testsTests come from capped scenarios; code writers cannot edit them; humans test by hand.No worse than software written by people.
The human becomes the bottleneckFounding concentrates effort at the start; frames are capped whole; autonomy widens decision by decision.Labelling fixtures is now a recurring cost as well.

Open questions

Answered in 0.4

  • Can small models handle the signals? Yes for the format; for judgment, when they are read rather than asked.
  • Does one decision per target hold on unseen cases? Yes: 10/16 against 8/16 for the scout. The 8B is the probe model, since the 4B scored 7/16.
  • Can small models judge what no program can? At the bar: 6 of 11 cases only a model could see. The scout got 4 of the 5 new ones, so writing a decision still helps there.
  • Does code zone context help? Yes, for 🧩 and 🧹, with no contamination from a neighbour's bug.

Still open

  • Do instruments produce the facts and signals the fixtures assumed? First job of Level 0c, on a real Angular repository.
  • Can the same reading work for workers? Probes decide where a signal goes. Writing code is still generation, checked only by the Prover.
  • Which model per mode? The 8B read directly was best without zones; the 4B writing a note first was best with them, at about five times the time per call.
  • Does intent ripen well, and does the garden stay a garden? Untested since 0.3.
  • How far can autonomy go, and how should it be tuned? Thresholds, decay and quorums are still guesses, now joined by exam limits and zone sizes.
