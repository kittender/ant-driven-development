Concept draft 0.3, October 2026

Ant-Driven Development

A way to build software with many small, short-lived AI agents that never talk to each other. They leave signals in the code, a deterministic environment does the counting, and nobody is in charge.

The idea

A single large agent loaded with a complex task accumulates sunk cost. Its context fills with its own assumptions, and when one of them is wrong it tends to loop on it. The usual fix is an orchestrator directing sub-agents, which moves the problem up one level.

Ant colonies solve hard problems differently. Each ant is simple and replaceable. Ants coordinate by changing their environment: one leaves a chemical trace, the next reacts to it. Traces evaporate, so mistakes fade. No ant holds the plan.

Ant-Driven Development (ADD) applies that to software. An ageant is a small-model agent that does one tiny job on one target and then dies. Ageants read and leave emoji signals. A set of deterministic programs, the Ecosystem, counts those signals, lets them decay, and checks every claim of success. A large model, the Queen, only designs new kinds of ageants when the colony lacks one. What the colony knows to be true, its approved specification and practices, is stored as honey and fed to every ageant that needs it. How the software is built is kept in a garden of small plans, tended by a planning caste that never writes code.

Three things are hoped for. Changes small enough that a human can still follow what happened to the code. Contexts small enough that they do not degrade. And work that runs mostly on small models, including ones on the developer's own machine. None of this is demonstrated yet. The first goal is to find out whether a colony works at all, and cost comparisons come after that.

ADD borrows the mechanisms and not the romance. Where biology does not fit software, this draft says so.

Three layers

Intelligence is spent where it is cheapest to verify. The largest model works rarely and only on design. Small models do the volume. Everything that must be predictable has no model in it at all.

Castes

All ageants come from the same few base models. What makes a caste is its genome: a short prompt, a strict list of tools, and the signals it reacts to. The harness enforces the tool list, so a worker cannot kill a process even if it decides to.

Worker is the broadest caste, and most genomes the Queen writes are workers. Typical ones: tester, debugger, scaffolder, ripener (refines specification, see Honey) and undertaker (removes dead code and expired journals, as real ants carry out their dead).

Where the biology is stretched. Leafcutter gardeners are the smallest workers in the nest. ADD gardeners run on the largest models, so the name borrows the job and not the size. The nobles of earlier drafts are gone: nothing in the colony implements a large change in one go. Real soldiers face outward. The closer model for ADD soldiers is social immunity: workers that remove infected nestmates and destroy eggs that should not exist.

The trail language

A signal has one form: an emoji on a target, repeated to show strength.

rechercher-credit.component.ts     ✅ 🧪🧪🧪 👀
rechercher-credit.component.html   ❌ 🐛🐛
credit.service.ts                  🔒 ⭐ 📌

Emojis almost never appear in source code, so the channel cannot be confused with comments, documentation, or the code itself. A program can find every signal with a plain text search.

Requests, which any ageant may deposit

A request says "something is needed here". It is safe to let a small model emit one, because a wrong request costs one wasted micro-task and then decays.

Verdicts, which only the Ecosystem or a human may issue

A verdict says "this is true". An ageant that could write ✅ would write it confidently when wrong, and the trail would then reinforce the error. So verdicts come from programmatic proof or from a human, never from self-report. A verdict emoji written by an ageant is ignored and logged against it.

Every emoji in the dictionary is a single Unicode character that displays as an emoji by default on current Windows, macOS, Linux, Android and iOS. Skin tones, joined sequences and characters that need a hidden variation selector (such as the warning triangle) are excluded, because small models and some editors mangle them.

Strength by repetition

Reinforcing a signal means adding one more of the same emoji. Decay means the Clock removing one at that signal's own rate. A threshold is a count. Agreement between independent ageants therefore shows up as strength, and a lone mistaken signal fades on its own.

t0🧪A scout marks a method
t1🧪🧪A second scout agrees
t2🧪🧪🧪Threshold 3 reached, a tester is woken
t3✅Test added and passing, request cleared
elsewhere, t1🐛One ageant suspects a bug
elsewhere, t3Nobody agreed. It evaporated.

Attract, repel, and fade at different speeds

A trail made only of attractive signals has a known failure. Army ants sometimes follow each other's trail in a closed circle until they die of exhaustion. The software version is an ageant retrying a fix that has already failed, drawn back by the same ❌.

Pharaoh ants avoid this with a second kind of pheromone, a "no entry" mark left at dead ends. ADD has the same: ⛔. An ageant whose change fails proof leaves one on the target. The Sensor never sends the same genome back to a target carrying ⛔. It sends a different one with the failed diff attached, and at the threshold it escalates in two directions. The target goes to a gardener for a plan, and its honey cell goes back to ripening, in case the cell itself is too large or wrong.

The same ants also use short-lived and long-lived trails. In ADD each signal has its own decay rate: a review request fades in minutes, a dead end is remembered for hours.

Where signals are written

  • One journal per ageant. Ageant leni03 can write to ant-leni03.md and to no other trail file. The harness enforces this, which gives every signal an author without trusting the ageant to sign its work.
  • One rendered view per folder. The Ecosystem reads all journals, applies decay and proof, and writes a read-only trail.md at each folder root. Ageants read this file and never write it.
  • Inline, when a signal concerns a block. Where the file type allows comments, a line such as // trail: 🧪🧪 ❓ sits above the block and moves with it. The Ecosystem maintains these lines too.
# ant-leni03.md, append-only, one signal per line
rechercher-credit.component.ts#onSubmit 🧪
rechercher-credit.component.html ❓

Signals, not sentences

It is tempting to let the emojis combine into phrases and questions. This draft recommends against it. Real ants manage with roughly ten to twenty chemical signals and no syntax. Meaning comes from where the signal is and how strong it is.

A language with grammar

credit.service.ts  🔒❓🧪
form.component.ts  🚫🧪👀
utils.ts           🔥💀
  • Order is ambiguous. Line one could mean "locked, but is it tested?", "should this be locked? add tests", or three unrelated remarks.
  • Negation has no scope. Line two: "do not test, review instead", or "there are no tests, please review"?
  • Everyday meanings leak in. Models learned emojis from social media. 🔥 reads as "excellent" and as "on fire". 💀 reads as "dead" and as "that was funny".
  • A question needs an answer. Who replies, where, and when is it closed? That is a conversation with state, which is what the trail is meant to avoid.
  • A program cannot count it. The Clock and Sensor would need a model to understand the trail, and the physics would stop being deterministic.

Signal × strength

credit.service.ts  🔒 🧪🧪
form.component.ts  👀👀👀
utils.ts           ⭐
  • One reading only. Each emoji means one thing, in any order. Repetition means "more ageants think so".
  • A caste learns two or three signals, the ones it reacts to and the ones it may emit. It never needs the whole dictionary.
  • Counting is trivial. Thresholds and decay are integer arithmetic in a binary.
  • Doubt has its own signal. ❓ on a target replaces every possible question. A scout turns it into something actionable.

What one ageant actually has in its context

The Sensor does the sensing. When a threshold is crossed it wakes an ageant and hands it a task written in plain words, with the honey that applies. The small model reads at most one line of trail and chooses its deposits from a closed menu.

GENOME        about 150 tokens, written by a Queen
You write one unit test for one scenario. Change nothing else.
If you cannot, deposit ❓ and stop.

HONEY         the capped scenario this test must encode
🍯 Given the amount field is empty
   When I submit the search
   Then I see "Montant requis" and no request is sent

GARDEN        the plot that applies
🍄 Components never call HttpClient. They go through CreditService.

TERRAIN       the method, its 📌 contract, one ⭐ example test
...

TASK          written by the Sensor, not by another ageant
Add one unit test for onSubmit() in rechercher-credit.component.ts

LOCAL TRAIL   one line from trail.md
rechercher-credit.component.ts  ✅ 🧪🧪🧪 👀

YOU MAY DEPOSIT
❓ 👀 🐛 ⛔ 🧩 🙋

The order is deliberate. What stays the same from one ageant to the next comes first, and what changes comes last. Hosted providers bill a repeated prefix at a fraction of the normal input price, and local runtimes can reuse the work already done on a prefix they have seen. Ageants that share a genome and a target therefore do not each pay for a full read of the same file.

The context stays small and holds nothing left over from another ageant's reasoning. A wrong assumption cannot be inherited, because assumptions are never passed along. Only the signal and the code are.

A cost to keep in mind. Emojis are distinctive but not cheap: one emoji is often two to four tokens. Short trails per target, not long ones, keep this negligible.

Life of a signal

Example: tests start failing

  1. The Prover runs the suite after a change. Four specs fail.❌ ❌ ❌ ❌
  2. The Sensor sees ❌ above threshold in one folder and no living caste that reacts to it. It starts a Queen session.
  3. The Queen takes the "debugger" template, writes three variants on different models, and spawns one per failing spec.
  4. Each makes one small fix. The Prover re-runs. Three pass. The fourth is retried by a different variant.✅ ✅ ✅ ❌

Honey, the colony's long memory

The trail says what needs doing and it evaporates. A colony also needs a memory that stays: what the software is supposed to do, and how this team writes code. In a hive that store is honey, and what feeds an ageant is specification.

Two memories

TrailHoney
SaysWhat needs doing hereWhat is true, and how we do things

Written byAny ageant, in its own journalRipened by ageants, sealed by a human

This keeps the earlier rule intact. Emojis are how ageants signal each other. Plain language is for the content of the work, and honey is where that content lives once it is trusted.

Frames and cells

Honey uses two formats developers already know. A frame is one user story. Each cell in it is one acceptance scenario written as Given, When, Then, and each scenario is checked by one test.

# honey/credit-search/search-by-amount.md      one frame, one user story
As a credit advisor
I want to search credits by amount
So that I can find a client's file quickly

🍯 Scenario: empty amount
   Given the amount field is empty
   When I submit the search
   Then I see "Montant requis" and no request is sent
   test: rechercher-credit.component.spec.ts > rejects an empty amount

🍯 Scenario: amount with no match
   Given no credit has the amount 12 000
   When I search for 12 000
   Then I see "Aucun résultat"
   test: rechercher-credit.component.spec.ts > shows the empty state

# honey/practices/unsubscribe.md               a practice cell
🍯 A component that subscribes in ngOnInit unsubscribes in ngOnDestroy.
   test: lint rule no-leaked-subscription

A human caps a whole frame in one reading, which keeps the number of decisions low. Practice cells describe how the team writes code, and each is backed by a lint rule or a ⭐ example. Ageants can read the store and cannot write to it: a ripener proposes a frame in its journal, and it enters the store only when it is capped.

Red, then green

  1. A human states an intent. Scouts gather it and ripeners write it up as a frame of candidate scenarios.
  2. The human reads the frame, corrects it and caps it.🍯 🍯 🍯
  3. A tester writes one test per capped cell. It fails, because the code does not exist yet. That failure is the smell of food.❌ ❌ ❌
  4. Workers write the smallest code that passes. The colony goes quiet when every cell is green.✅ ✅ ✅

Whoever writes the code cannot touch the test. The Warden never grants a code-writing genome a lease on the test of the same cell, and a test changes only when its cell changes. Otherwise the cheapest way to earn ✅ is to weaken the test.

Honey does not spoil, but intent does

Real honey keeps for years. A specification does not: the product changes and a sealed cell becomes wrong. Only a human can uncap a cell. Uncapping sends it back to ripening, marks its test as stale, and puts 👀 on the code that was built from it.

Proof has a limit that honey makes visible. The Prover can show that code matches a cell. It can never show that the cell is what the human wanted. That judgment stays with the human, which is why capping a feature frame stays with them unless they decide otherwise in the autonomy settings.

Bugs that a human finds by using the software come back the way they do in any project: as 🐛 on the code, or as a new scenario in the frame. A colony needs manual testing as much as a human team does.

Do ants store honey? A few do. Honeypot ants keep sugar in the swollen bodies of living workers that hang from the nest ceiling and feed the others on request. The ripening and capping described here are borrowed from bees.

The garden, where the plan grows

Honey says what the software must do. It does not say how the software is built, and good cells do not add up to a coherent structure by themselves. Something has to hold the plan, and in ADD no ageant may.

Leafcutter ants offer the model. They do not eat the leaves they carry home. They feed them to a fungus, and eat the fungus. The garden is alive: a caste of small workers weeds and prunes it without pause. ADD's garden is the architecture and the implementation plan. It turns honey into something workers can act on.

A plot

# garden/credit-search/data-access.md          🍄
Decision   Components never call HttpClient. They go through CreditService.
Because    One place for caching and for mapping errors.
Proof      lint rule no-http-in-components
Contract   📌 credit.service.ts  search(criteria): Observable<Credit[]>
Steps      1. credit.service.ts#search
           2. rechercher-credit.component.ts calls the service
  • One decision per plot. A plot is as small as a cell, so no gardener has to carry the whole architecture in its context.
  • Steps become seeds. When a plot is grown, the Ledger places 🌱 on each step's target. That is how a plan reaches the workers without anyone handing out tasks.
  • Proof where a program can give it. A dependency rule, a lint rule or a type can enforce a decision. The plot names it and the Prover runs it. 📌 contracts are produced by plots.
  • Plots are weeded. A gardener can propose replacing a plot. The old one is removed and not kept beside the new one. Its history stays in the Ledger.

What gardeners do

Gardeners run on larger models and never write code. A gardener is started by one of these: a capped frame that no plot covers, 🧩 from a patroller, ⛔ piling up on a target, a plot whose proof has started to fail, or the same code appearing in several places.

They review each other through the plots. A gardener that supports a proposed plot reinforces it with 🌱. One that doubts it leaves ❓, or proposes a competing plot. When gardeners on different models bring a plot to quorum, it is grown. This is the one place where ageants work toward a shared text, and they still never message each other: each one reads the plot and leaves a signal or a revision.

Patrollers are the garden's eyes in the code. They read every change that lands, with the files around it, and can only leave signals. A reviewer on a large model reading every diff would bring back the cost and the worn context ADD is trying to avoid, so the reading is done by a mid-size model and the thinking is escalated only when 🧩 accumulates.

The Ecosystem

The Ecosystem is the physics of the colony. It contains no model. What protects it is not that it is compiled but where it lives: its binaries, configuration and ledger sit outside the ageants' sandbox, under a different system user. An ageant can no more edit the decay rate than an ant can edit evaporation.

ProgramRole
ClockRemoves one unit of each request signal at that signal's decay rate. Expires leases, cooldowns and alarms.
SensorWatches the directory and journals, counts signals per target, and wakes a caste when a threshold is crossed. Starts a new Queen session when a need stays unanswered. Attaches the applicable honey and plots to every task.
ProverRuns on a heartbeat and not after every change. When enough changes have finished it pauses spawning and runs the proof. Each change is its own commit, so a red run is bisected to the change that caused it. Issues ✅ or ❌, routes to 🙋 when no proof exists, and lets work reach the main branch only when green.
LedgerRecords which ageant, from which genome, deposited or changed what, and when. Renders trail.md. Guards the honey and garden stores, and turns the steps of a grown plot into 🌱. Keeps the colony log.
WardenGrants file leases, enforces cooldowns, detects loops, reverts and budget overruns, executes kills, enforces the population limit.

Leases instead of good manners

"Never edit a file someone else is editing" cannot be left as a rule in a prompt, because prompts are followed most of the time and not all of the time. An ageant asks the Warden for a lease on its target. The Warden grants one holder at a time and shows it as 🚧. The lease expires on the Clock, so a crashed ageant never blocks a file for long.

After a change lands, the target rests for a short cooldown before the Warden leases it again, the way a neuron cannot fire twice in a row. Together with revert detection (a diff that undoes an earlier diff raises 🔁), this stops two ageants from undoing each other's work indefinitely.

Reflex, tool, plan

Deterministic work should be done by deterministic means, but something still has to decide that it is needed. Three levels cover it:

  • Reflex. A rule inside the Ecosystem with no ageant involved. A saved file is formatted and linted. A new component folder is checked for its three files.
  • Tool-holding worker. Deciding that a scaffold is needed is a judgment. Running it is not. A worker reacts to 🌱, picks from a whitelist of commands, and the Prover checks that the files exist and compile. "Run this script" is a legitimate ant genome.
  • Plan. When a need spans several files, a gardener writes a plot whose steps become micro-tasks. A wide but mechanical change, such as renaming a symbol across forty files, is a refactoring command run by a tool-holding worker.

Always use the lowest level that can do the job.

Autonomy is a setting

How much the colony decides alone is configured per kind of decision, in the same spirit as auto-approving tools for a single agent. The defaults above keep intent, contracts and anything a program cannot check with the human, and let the colony grow its own plans. A team can loosen or tighten each line as it gains or loses trust. The settings live with the Ecosystem, so no ageant can change its own freedom.

The colony log

The Ledger also keeps one time-ordered log of everything every ageant received, produced and called, together with the cause of each start: which signal crossed which threshold. Any change can be traced back to the signal that triggered it, and that signal to the one before. The log is for the humans who watch the colony. No ageant can read it.

The immune system

In this colony the enemy is always inside: an ageant that loops, claims what it did not do, or carries a polluted context. The defence is modelled on immunity, which has the same three problems ADD has. It must find bad cells, it must not attack healthy ones, and it must be able to remove its own faulty defenders.

  1. Tag. A soldier compares an ageant's claims with the Prover's results and the diff. If they disagree it flags the ID, attaching the evidence.@leni03 🚩
  2. Quorum. A second, different soldier reaches the same conclusion on its own. Flags decay like any signal, so a lone accusation fades.@leni03 🚩🚩
  3. Kill. The Warden, not a soldier, terminates the process. No single ageant can kill another.@leni03 💀
  4. Caution. The ageant's past work stays. The Ledger adds 👀 to every target it touched, so other ageants re-examine it.👀 👀 👀

Termination does not erase work. It lowers trust in it. This matters because trails evaporate but code does not: a wrong edit stays wrong until something looks at it again. The automatic 👀 is what makes that happen.

Who polices the soldiers

Soldiers are ageants and can be flagged like any other, including by other soldiers. Three further guards are programmatic:

  • An entrance exam. Before a new soldier genome is released, the Warden shows it a small set of cases with known answers, some good work and some planted faults. A soldier that condemns good work or passes a planted fault is never spawned. The body does the same: immune cells that react to healthy tissue are destroyed before they leave the thymus.
  • Canaries. The Warden keeps slipping known cases into the soldiers' normal flow. A soldier that gets one wrong is terminated without needing an accusation.
  • The watchdog. Mechanical failures need no judgment and no soldier: the same diff twice, too many steps without proof, budget exceeded. The Warden kills on these directly.

This mirrors how model-based graders are usually kept honest: prefer checks written as code, give a model judge one narrow question with a clear rubric, and calibrate it against examples a human has already labelled.

Does the body have anti-antibodies? In a sense, yes. Regulatory T cells calm down an immune response that goes too far, and antibodies can be raised against other antibodies. The flagging idea itself is real biology too: antibodies do not kill, they coat a target so that other cells recognise and destroy it.

Diversity by design

Ants make independent mistakes, so numbers cancel them out. Copies of one model make the same mistake together, so numbers amplify it. Repetition only means something in ADD if the ageants that agree are different from each other.

  • Rotation for the model. When several ageants answer the same stimulus, the Queen cycles through the available base models so that no two share one. This is a guarantee, so it should not be left to chance.
  • Seeded randomness for the rest. Temperature, wording of the genome, and which example is shown vary from one individual to the next. The seed is recorded.
  • The Queen's own variation is welcome. She should not stamp out identical ageants. Each individual is a slightly different reading of the template.
  • The Queen rotates too. Every Queen is a new session with no memory of the last, so nothing forces them all onto one model. Rotating the Queen's model keeps a single bias out of every genome.
  • Every genome is kept. The Ledger stores the exact genome of each ageant with its outcome. Variation that is recorded lets the Queen favour what worked and lets a bad template be retired. Variation that is not recorded is just noise.

Birth, death and the end of work

  • Birth. An ageant is born for one stimulus on one target, with a name given by the Queen and an identity stamped by the Ledger.
  • Death by completion. When its micro-task ends, proven or not, the ageant ends. A fresh context is cheaper than repairing a used one.
  • Death by old age. The Warden enforces a maximum lifetime and step count. No ageant is asked to judge its own health, since a faulty one is the least able to.
  • The Queen lives for one design. She does not sleep between needs. Each need starts a new session that reads the templates, the honey and the Ledger's record of which genomes worked, writes its genomes and ends. Her memory is in those files, so she starts every time without a worn context.
  • Soldiers end when no other ageant is alive to watch.
  • The colony is quiet when no signal is above its threshold, every capped cell is green, and no Queen session has been started. Nothing declares the work finished. Activity stops because nothing calls for it, and resumes when the human adds intent or a proof starts failing.

Founding, work and rest

A real colony begins with a queen alone, raising the first workers herself. An ADD colony begins with a human. During founding, the human works closely with ripeners and gardeners to settle the core frames, the first plots and the first contracts. This is when the colony asks the most of a person.

After that the colony alternates. In work phases the human mostly caps new frames and answers 🙋. In rest phases nothing moves: no signal is above threshold, no ageant is alive, and the colony costs nothing until intent changes again.

Alarm, the colony's emergency mode

A flooded fire-ant nest forms a raft and a threatened colony mobilises at once, yet no single ant holds the picture. An alarm pheromone lowers every ant's threshold for the same response. ADD keeps this: 🚨 from the Prover, for instance when the main branch stops building, suspends ordinary work and wakes every caste able to help. It is a change of mode and not a single mind. Work that needs one head holding many files goes to a gardener, who plans it and does not write it.

The laws of ADD

  1. Physics is not negotiable. Decay, thresholds, proof, identity and death belong to programs that ageants cannot reach or argue with.
  2. Proof before praise. A verdict comes from programmatic proof or a human. Where neither is possible, an ageant asks for a human with 🙋.
  3. One ageant, one micro-task, one life. Prefer the smallest change that can be checked.
  4. Signals, not sentences. One emoji, one meaning, strength by repetition. Ageants never message each other.
  5. The trail evaporates, the rest must earn its place. Requests, leases, flags and alarms all decay, each at its own rate. Code, honey and the garden stay, so code must be proven, honey capped and plots grown.
  6. The Queen designs and never commands. A new Queen session starts on an unmet need, writes genomes, and ends.
  7. Nobody kills alone. Soldiers accuse, a quorum confirms, the Warden executes. Soldiers are subject to the same rule.
  8. Agreement only counts between different minds. Mix models and vary genomes, and record every variant.
  9. Lowest level first. A reflex before a tool, a tool before a plan.
  10. Honey before code. A capped cell and its failing test come first. Whoever writes the code cannot touch the test.
  11. Mark the dead ends. A failed attempt leaves ⛔, and the same genome is never sent back to it.
  12. Planners never build. Gardeners write plots and workers write code. No ageant does both.
  13. Autonomy is configured. What the colony may decide alone is written down by humans, in a file no ageant can reach.

Experiments, in order

Each step tests one assumption and needs only the parts built before it.

  1. Signals. Give several small local models a target, one line of trail and the closed menu. Measure how often they deposit a valid signal, and the right one. Everything else depends on this.
  2. One loop. 🧪 on a method, a tester with a hand-written genome, the Prover, ✅. No Queen yet.
  3. Decay and dead ends. Add the Clock and ⛔. Plant a task that cannot be done and check that the colony stops trying.
  4. The Queen. Raise a need no caste answers and let her write the genome from a template.
  5. Honey to green. One real user story, from frame to passing tests, with a human capping.
  6. The garden. A second story that must share code with the first. This is the test of whether a plan can live in plots.

Open questions

  • Can small models handle the signals? The design keeps their part minimal, but the closed menu and the single-character rule have to be tested on real local models. It is the first experiment for that reason.
  • Does intent ripen well? Scouts gather a request and ripeners write frames. Where several ripeners propose the same scenario it is probably right. Whether good frames emerge without any ageant holding the whole request is unproven.
  • Does the garden stay a garden? Plots are meant to stay small and be weeded. The risk is a store that only grows, until gardeners need a huge context to tend it and ADD has rebuilt the large agent it set out to avoid.
  • How far can autonomy go? Visual design, wording and product choices have no programmatic proof. The settings allow handing them to the colony, and only use will show where that stops being safe.
  • Tuning. Tick length, decay rates, thresholds, heartbeat, cooldown and quorum are guesses. They are settings, so a team can adjust them by watching the colony work.
