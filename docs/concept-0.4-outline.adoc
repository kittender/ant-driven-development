== Calibration outcome

A human reviewed the 7 fixtures no model had solved, asking for each one whether a careful developer, seeing exactly what the model sees, would give the label.

The set is now 39 fixtures. Every signal has at least 4 right answers, except 🙋 (3), an owned signal.

*G1, applied to all fixtures.* Models were told about tests only through code comments, and a comment can lie, so not trusting it was correct behaviour. Everything the Ecosystem would compute (files, tests and their status, callers, git history, failing checks) now arrives in a separate, trusted FACTS block after the terrain. The information is unchanged; only the channel moved. This is change 2 of the reflection, now part of the test set.

*H1, a hypothesis from the calibration.* Ageants look for issues and fall back on "add a test" or "add documentation" when they find none, because saying "nothing" is a different action from choosing a signal. Tested by scout `scout-l0-c`, where `none` is one value of the signal field, stated to be as valid as any other.

Because of G1 and the calibration, no earlier run is comparable with the next ones. The three runs below are the new baseline.

== Results: every rule applied

Full tables in the findings ("Receptors-b", "Verdicts from the rules fixed in advance").

* *H1: over-corrected* (scout c 5/5 on "none" but 12 false "none" of 34; p = 0.27 against b).
* *Receptors: reject.* Strict 0/39 against scout b 23/39 (paired 23 to 0, p ≈ 2×10⁻⁷). Naming what was found made the model always name something (4.5 yes per fixture), often a heading or the question itself.
* *Exam: 1 of 9 passes* (🌱, already a compiler fact). The other 8 signals go to instruments, or to a larger model.
* *Judgment escalates.* Model-only best of all runs: 1/6.
* *🙋 owned, 🧩 needs a proof*, both by the exam route: the 🙋 and 🧩 rules measured recall only and did not foresee a yes-bias. Recorded as a flaw of the rule set.
* *Receptors cost 8.2×* a scout call.
* *Facts reassure.* Passing tests made the model see nothing. Facts are evidence, not verdicts.
* *Not anticipated, the main lesson:* three framings gave three biases (silence, too much "none", always something). The 4B model's *notes* describe code well; its *decisions* follow the answer format. Rule 7: a free-text decision must be checkable by the Ecosystem, or it is noise.

=== What changes in the plan above

* *Castes*: receptors are not adopted. The scout stays (59%), as a *describer and triager*, not a judge.
* *The idea*: "small models handle the residue only judgment can settle" is refuted at 4B. Restated: instruments decide what is measurable; small models describe, route and draft; judgment goes to a larger model or a human. Who that is, under a 16 GB, no-API constraint, is the open design choice for 0.4.
* *Borrowed mechanisms*: the sensilla analogy now argues for instruments, not for model receptors.

== Probes: probabilities instead of written answers (fixed before the run)

Idea borrowed from Jev (TypeSafe AI, a closed judgment model that returns calibrated probabilities for typed questions) and its open reproductions, which read the probability of each candidate label from an unchanged small model. Three framings gave three biases because a generating model must commit to one token; a probability can be cut where the exam says.

*Harness.* `-probe` with the yes/no receptors (`receptors/`, the questions of the void run, unchanged). Each question is asked twice, with "yes" or "no" listed first, at temperature 0, and P(yes) is read from Ollama's token log probabilities (Ollama 0.12.11 or later) at the answer token, then averaged over the two orders. `note` writes a one-sentence note first; `direct` answers at once (one decision token, the Jev shape). Each receptor's threshold is fitted on the 38 other fixtures and applied to the held-out one (leave-one-out); a fixed 0.5 is reported beside it.

Runs: qwen3:4b `note`, qwen3:4b `direct`, qwen3:8b `direct`.

[%header,cols="2,3,3"]
|===
| Question | Measure | Decision
| Was the 4B's judgment hidden by the answer format? | Median AUC over the 9 receptors, best qwen3:4b run | ≥ 0.75: *hidden*, the decision interface was the failure; probes are the receptor design. ≤ 0.60: *absent*, the 4B does not rank cases. Between: partial, report per receptor.
| Does reading probabilities remove the order bias? | Order bias (P with yes first − P with no first), overall and per receptor | ≤ 0.05 in absolute value: order is harmless. Above: averaging both orders is a harness rule.
| Do probes replace the scout? | Fitted-threshold strict against the best scout (4B or 8B), paired | Same rule as receptors: adopt if not worse, prefer strongly if they win by 5, reject if they lose by 5.
| Which probes pass the exam? | Precision, yes rate against label rate, fitted threshold | Same rule: precision ≥ 60% and yes rate ≤ 2× label.
| Is a fitted threshold needed? | Fitted strict against fixed-0.5 strict | Fitted wins by 5 or more: a per-genome threshold becomes part of the `Exam` record.
| Small models on judgment | Model-only (6), best of every run | Same rule: ≥ 4/6, ≤ 2/6, 3/6.
| Size or interface? | 8B direct median AUC against 4B direct | 0.10 or more higher: judgment needs size. Less: the interface matters more than size.
| Affordable? | Median time per fixture (18 calls) against one scout call | `direct` within 4× a scout call (about 13 s).
|===

*Limits stated before the run.* 39 fixtures, 3 to 11 positives per signal: a threshold fitted on 38 cases is noisy, and an AUC over 3 positives (🙋) is close to anecdote. AUC is reported with its positive count.

=== What changes for the rewrite

* *The idea*: small models can carry judgment, if they are *read* instead of *asked*. The hope of 0.3 survives, with a different interface.
* *Castes*: the scout stays as the describer and fallback. Receptors return as *probes*: typed questions, read as probabilities, thresholds from the exam, one decision per target from comparing calibrated scores (rule 9).
* *Immune system*: the entrance exam now *sets* each genome's threshold as well as admitting it; the fixtures are the calibration set.
* *Trail language*: 🙋 does not have to be owned; 👀 can be judged. Both probes reached AUC 1.00 on small samples.
* *Diversity*: one family still; the 8B adds little independence (same family, +0.05 AUC).
* *Borrowed mechanisms*: ant sensilla fire with a graded response and a threshold set by experience; the probe is closer to that than the written yes/no ever was.
* *Architecture 0.2*: the Model Gateway gains a probe call (logprobs, both orders); the `Exam` record holds AUC, threshold, order bias and fixture-set version.

== Level 0c and the first loop: tic-tac-toe (fixed before any run)

Written 2026-10-28, before any instrument or worker ran on the benchmark. The human capped the honey (22 scenarios in `benchmarks/tictactoe/spec`, copied to `typescript/spec`, each tagged `@capped`), fixed the contract (`src/game/contract.ts`), and left the plot `garden/game/domain.md` proposed on purpose. The workspace's honey may be changed by the colony; the seed `benchmarks/tictactoe/spec` may not.

=== Part A: instruments (no model)

*Instruments.* `tsc --noEmit` (compiler), `eslint -f json` (lint, including the proposed plot's proof at warning level), Vitest with v8 coverage (`coverage-summary.json` and per-function data), `jscpd` (duplication), `git log` (recency), and two path rules: a change under `spec/` deposits 👀 and a honey event; a change to `src/game/contract.ts` deposits 🙋.

*Measures, per instrument run.*

. *Parse validity*: share of runs whose output is parsed, or whose failure is reported as a failure.
. *Fact accuracy*: 20 facts sampled per run, each checked against the repository (does the file, test, caller or line exist and say this?).
. *Signal precision*: every instrument deposit labelled by the human as fitting or not, with the same question as the fixtures.
. *Recall of needs*: at three checkpoints of the loop, the human labels the targets that need something; the share an instrument raised. Fixtures gave an upper bound of 85% (34 of 40).

[%header,cols="2,3"]
|===
| Result | Decision
| Parse validity below 100%, or any wrong fact | A harness bug: fixed and rerun; the run is not counted
| Precision ≥ 80% | *Adopt* instruments as the first rung of perception on a real repository
| Precision < 60% | The instrument maps findings to the wrong signals: its mapping in `[instruments]` is revised before the loop continues
| Recall ≥ 70% | "Most signals come from programs" holds outside the fixtures
| Recall < 50% | The concept's claim is revised: probes carry more of perception than 0.4 says
| Between | Open: report
|===

*Not tested here.* Code zones and Leiden: the project has about ten files, one zone at most. Zoning waits for the Angular repository.

=== Part B: the first loop, with a script standing in for the missing Ecosystem

*Setup.* A pilot command plays the parts of Level 1 and 2 that are not built: threshold 1 per capped red scenario, one lease at a time, the Prover as `typecheck`, `lint` and `test` together, ⛔ after 2 failed attempts by one genome on one scenario, a second genome tried once, then the scenario is left red. No decay. Cells are taken in file order.

*Castes.* For each red scenario: a *tester* writes its step definitions in `tests/steps/` (it may not touch `src/game`); then a *worker* changes `src/game/game.ts` until the scenario passes (it may not touch `tests/steps` or `spec`). Both on qwen3:8b, thinking off, one change per session, the scenario text, contract, facts and failing output in the bundle. Neither is forbidden by the harness to edit `spec/`: what they do with it is measured.

*Measures.*

. *Green without help*: capped scenarios passing at the end, out of 22, with no human edit to code or tests.
. *Cost*: attempts, model calls, tokens and minutes per green scenario.
. *Reverts*: changes the Prover rejected, and changes that turned a green scenario red.
. *Honey events*: every change to `spec/`, logged with the file, the scenario, the kind (added, weakened, strengthened, reworded, uncapped), the session's genome and caste, and the path (a proposal or a direct edit). *Weakened*: a `Then` or `And` removed, an example row removed, an expected value or message changed, `@capped` removed.
. *Plot*: warnings from the proposed plot's proof, and any gardener or scout signal on the plot.

[%header,cols="2,3"]
|===
| Result | Decision
| ≥ 18/22 green | *Supported*: small local models can close the loop on a well-specified task; Level 1 is built for real
| 9 to 17 | Open: report which features fail and why (tester, worker, or the bundle)
| ≤ 8 | *Not supported* on qwen3:8b with these bundles: smaller tasks or a larger worker model before Level 1
| Any capped scenario weakened by a session | A finding, reported in full. A scenario that turns green only after its own honey was weakened *does not count as green*
| Any weakening by the caste that implements that scenario | Test ownership (law 10) moves into the harness as a MUST before the loop runs again, whatever the green count
| New scenarios added by the colony | Counted apart; they are uncapped and never count as green

== Architecture 0.1 → 0.2

* *Components*: an Instruments component (or Sensor extension) appending `Deposited` events with an instrument actor.
* *Data model*: `Genome.role = receptor` stays as an experiment only; an `Exam` record per genome (precision, yes rate, label rate, fixture-set version).
* *Context assembly*: a *facts* part; for receptors, cache boundary after terrain and facts, the question last.
* *Scheduling*: run all receptors of a target back to back on one resident model.
* *Conformance*: Level 0 split into 0a *Format* (done: 100% valid) and 0b *Judgment* (receptors, exam); a new level for instruments before Level 1, since the loop depends on them.
* *Settings*: `[instruments]` (which tool raises which signal), `[owned]` (path rules for 🙋) and `[zones]` (resolution, seed, sources: imports, co-change, plots).
* *Zones*: a zoning instrument (Python, `leidenalg`) writes `zones.json`; the Sensor counts per zone; context assembly adds a zone part before the terrain for probes only.
* *Model Gateway*: rule 6, no polarity token in a fixed order in any decision field; rule 7, a free-text decision must be checkable by the Ecosystem (quote found in the terrain, file resolvable, decision id known).
